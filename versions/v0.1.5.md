# 0.1.5：重复 NAL 解析消除与解码阶段抽样

日期：2026-10-27。候选 `0.1.5-atk-profile`。

## 修改及边界

0.1.4真实手机显示6.050 FPS，区间解码约102ms、转换22ms、LCD提交16ms。继续保持320×192/maxFPS30与CPU240/PSRAM80，先测清解码内部成本。

- 生产封装将NAL预检时生成的RBSP保留到实际解码使用，取消第二次NAL解析、RBSP去转义及分配/复制。仍先检查整个AU的单slice I/P限制，再修改参考帧；最多16份NAL元数据在栈上，不增加视频队列。
- 每32个送入解码器的VCL AU抽样一次，从首个开始，序号跨解码器重建保留；仅成功出图的样本加入累计统计。`local_display.decode_profile`记录样本数、IDR/P计数、时间戳读取次数、平均/最大解码耗时和6个互斥时间桶。
- 分类：other（语法、上下文推导、CAVLC及未覆盖工作）、cabac_bins（低层算术bin引擎）、intra_prediction、motion_compensation、inverse_transform、deblock。不是把整个CABAC解析归为bin成本；不用上游混合预测/变换工作的SectionProfile标签。
- 嵌套作用域只计入当前阶段，不重复计算；输出回调暂停计时，排除颜色转换与LCD提交。S3固定240MHz周期计数器使用无符号差值处理回绕；仅支持当前单解码任务所有权。
- 计时包含插桩开销、抢占及协作等待，不能视为纯CPU周期；bin级采样有扰动，未选中的帧也有分支成本。最终加速效果须用真实板端与手机对照，不能从主机计时或分类占比预先承诺。
- HTTP状态缓冲增加到12KiB；原采集脚本自动保留新字段，并在summary中标注为启动累计抽样值；诊断仍不上LCD。未改变码流算术、参考帧顺序、去块滤波、USB能力、显示/DMA所有权及触摸路径。

## 同一BOX升级前后模拟对照

固定同一320×192 High/CABAC文件，10FPS发送100帧，每10帧重复配置一次。两轮均100帧全部解码/LCD提交，errors/gaps均0，重复配置均9次，解码器均仅初始化1次。实际发送率均约10FPS。此测试由Mac生成输入，解码及LCD都在S3完成，不是实际iPhone性能。

四个成功抽样（1 IDR、3 P）共107,986次时间戳读取，样本解码均值50.843ms：other25.653、cabac_bins5.581、intra0.830、motion6.518、transform8.196、deblock4.064ms，舍入误差内合计一致。只有4个帧样本，且bin级计时自身有开销；other不等于某个可直接替换的算法，不能据此称CABAC整个解析只花5.6ms。详细公开数值见 [profile-simulation-2026-10-27.json](../references/profile-simulation-2026-10-27.json)。

真实手机阶段分布、画面观感及流畅度仍待采集。测试结束后的额外状态读取时USB已不在Mac总线上，未据此认定固件故障，也未声称完成长期稳定性测试。
