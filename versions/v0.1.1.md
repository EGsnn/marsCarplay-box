# 0.1.1：隐藏诊断页，等待关键帧时保持画面

固件版本 `0.1.1-atk-clean`，日期 2026-10-25。

## 问题与修改

用户在实际 iPhone 上确认 0.1.0 已能在 BOX 屏幕显示 CarPlay，但画面与数据页反复闪切。显示层会在视频缺口、配置更新或解码错误时清除 `have_frame`，随后每 250 ms 画一遍诊断页；新关键帧又覆盖它。

- 移除正常 LCD 流程中的协议计数、认证、网络和解码诊断数据页。
- 同一会话内等待配置/关键帧、遇到缺口或解码错误时保留最后一次完成的 LCD 图像，不用诊断页覆盖。依赖恢复仍重建解码器并等待 IDR，不把过期画面冒充为新帧。
- 启动和实际视频会话结束时只画一次黑底 `ATK BOX CARPLAY / CONNECT IPHONE`。所有 LCD 提交统一由视频任务持有。
- 等待时仍暂停触控回传；恢复有效帧后再启用。HTTP `/status` 保留诊断，并增加 `holding_last_frame` / `lcd_diagnostics:false`，区分旧图保留与有效新视频。
- 删除主循环到诊断 UI 的状态拷贝，连接提示的临时画布在 DMA 完成后释放。

本版解决诊断页覆盖导致的闪切；没有宣称解决造成缺口的解码吞吐或提升实际视频帧率。

## 验证

- S3 固件构建成功，最终 ELF 验证版本、板型、USB iAP2/NCM 描述符和本地解码路径。
- 最终 ELF 不再链接旧 `probe_ui_draw` 或旧 UI 状态拷贝入口；保留一次性连接提示入口。
- 原 H.264 内核、像素转换和触摸几何映射未改动。
- 候选 1,208,400 B，SHA-256 `a730eef902adaca4289e8c593bc081847a196fec343cf65cdc9bf6c43c13e0bc`。

## 安装与实物验收

已检测同一 BOX MAC `[device MAC omitted]`、16 MiB Flash / 8 MiB PSRAM。更新前用 ROM 校验当前全 16 MiB 与已保存的 0.1.0 全量镜像摘要一致，将该精确镜像复制为本版 `full-before.bin`，另存原应用槽供回退。实际分区布局、OTA CRC 和 `ota_0 @ 0x10000` 选择均重新核对。

本版仅写入应用。独立读回与候选逐字节一致；全 Flash 摘要与“备份仅替换应用擦除范围”的期望镜像一致，其他分区受保护。首次 watchdog 复位后设备仍在下载模式，用户松开 BOOT、复位后已正常启动并确认连接提示。

Mac 枚举为 ATK BOX CarPlay，经 USB IPv6 `/status` 确认 `0.1.1-atk-clean`、签名器 ready、RTSP listening、本地显示 ready、`lcd_diagnostics:false`。

2026-10-25 用户接回真实 iPhone 复测反馈：“只显示 CarPlay，不再闪切”。诊断数据页隐藏与闪切修复通过本次实物验收；此反馈不代表已测得持续帧率、端到端延迟或完成触控/长期稳定性验收。
