# 0.1.0：ATK BOX 本地解码显示首版

日期：2026-10-25。固件版本 `0.1.0-atk-direct`。

## 本版修改

- 建立独立的 code / versions / references 与 AI 入口 AGENTS.md，保留原微雪 0.8.2 已验收项目。
- USB、iAP2 与服务发现名称统一为 ATK BOX CarPlay / ATK-DNESP32S3-BOX；能力声明另存可编辑 probe_info.plist，由本项目生成器产生 C 头，保留已验证的协议字段和触摸尺寸。
- 冻结 BOX 的 I80 ST7789 / XL9555 / CHSC5432 驱动和生成的 320×240 板型头，独立编译，不加载 Mars 桌面/应用框架。
- 复用 iAP2 认证、身份、USB NCM、CarPlay 配对/事件/保活/视频解密链路；电脑不参与运行时视频传输、解码或转码。
- 替换原来的 4 MiB 录像缓存，以 384 KiB / 32 槽压缩帧队列连接接收与本地解码。单访问单元上限 192 KiB；网络正文上限改为 512 KiB。
- 接入固定 MIT Sub0h264 generic 路径；最大 800×480、最多 4 参考帧、8 bit 4:2:0、单 slice I/P。拒绝本版不支持的 B slice、多 slice 和裁剪参数。
- 本地 YUV420 → RGB565，以 320×192 显示 800×480 视频，顶部/底部各 24 像素黑边。颜色与实际行跨度分开处理；同步等 LCD DMA 完成。
- 一个任务独占解码和绘屏；接收不等待解码。掉依赖帧后清理解码器、重新喂配置并等 IDR，请求限频关键帧；配置代次变化后的旧结果不画到新会话。
- 独立触摸任务将画面区坐标映射到广告的 800×480 HID；黑边无点击，抬起保留最后位置；显示/解码忙时触摸轮询仍独立运行。
- Wi-Fi `ATK-CarPlay` 仅诊断；本地随机密码位于忽略的 local/settings.json。只提供状态 HTTP，不提供电脑预览/录像下载链路。
- 状态区分 decoded / shown / gap / error / waiting_idr，以及解码、像素转换、LCD 和总处理耗时。耗时是墙钟值，含调度，不宣称纯 CPU 或端到端延迟。
- 暂未加入 SilkFrame 补帧或音频播放，先验收真实本地解码、内存与速度。

## 已完成验证

- 实际源码路径已生成 ESP32-S3 固件，应用约 1.21 MB，未超过既有 0x440000 应用槽。
- 从最终 ELF 核对 0.1.0、BOX 320×240/16 MiB/8 MiB、iAP2+NCM 三接口、端点与 500 mA 描述，以及本地解码/转换函数已链接。
- 真实样本 SHA-256 `34013f07a777fdafb2b928211233e1e14d25416a89e9aa7bf6c79206fe0fcf86`：800×480、High、level 3.1、CABAC、8×8 transform、4 参考帧、逐行 8bit 4:2:0。
- 原内核 ASan/UBSan 解码 124 帧无报错；与 PyAV 比较亮度 PSNR 65.241 dB，最大亮度误差 3，124 帧中 9 帧三平面完全一致。
- 实际生产 C API + RGB 路径 ASan/UBSan 完整处理 124 帧，重建对象与不支持 slice 保护通过。RGB565 红绿蓝白、Y/UV 行跨度、横竖画面适配及触摸逆映射通过。
- 源码头中三处 uint8 与 256 的恒假比较触发主机编译警告；保留原上游实现，S3 组件单独处理该警告，未把它当作已修复的通用解析器安全保证。
- 新增只读备份检查工具，校验完整 16 MiB、分区 MD5、实际/候选分区一致性与 OTA CRC/选择；空 OTA0、有效 OTA1、拒绝待确认 OTA、坏 MD5 和不完整备份的保护检查通过。
